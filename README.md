# Автонарізка шортсів зі стрімів (World of Tanks, PUBG, STALKER 2…)

Інструмент знаходить найкращі моменти в записах стрімів і збирає вертикальні шортси
1080×1920 у DaVinci Resolve 21 (безкоштовна версія) так само, як ви робите вручну:
V1 — гра, V2 — вебкамера, V3 — лічильники шкоди, A1 — звук.
Усе працює локально на вашому ПК (NVIDIA), без хмарних сервісів і платних API.

## Стан розробки

| Етап | Що робить | Стан |
|---|---|---|
| 1 | Зоровий детектор WoT (лічильник шкоди, лог, міцність, екран смерті) + звіт | **готово, потрібна перевірка на вашому записі** |
| 2 | Розділення звуку (голос/гра), звуки гри зі зразків, детектор емоцій | далі |
| 3 | Відбір моментів, таймлайни V1/V2/V3 у DaVinci через кнопку в меню Workspace → Scripts | далі |
| 4 | Рендер MP4 (NVENC) з тим самим макетом | далі |
| 5 | Субтитри whisper.cpp + заклик у кінці | далі |

## Встановлення (один раз, ~30–40 хв, більшість часу — завантаження)

### Крок 1. Python 3.11
1. Відкрийте <https://www.python.org/downloads/windows/> і знайдіть **Python 3.11.x → Windows installer (64-bit)**.
2. Запустіть інсталятор. **Обов'язково** поставте галочку **«Add python.exe to PATH»** внизу першого вікна.
3. Натисніть **Install Now**. Нічого іншого не міняйте.

> Python 3.12 теж підійде. Не беріть 32-bit.

### Крок 2. Папка інструмента
1. Завантажте архів коду:
   <https://github.com/MrAntibiotik/git-script/archive/refs/heads/claude/wonderful-pasteur-vz3090.zip>
2. Розпакуйте його. Усередині є папка **`shorts-tool`**.
3. Скопіюйте **вміст** папки `shorts-tool` у **`C:\ShortsTool`**. Має вийти, наприклад, `C:\ShortsTool\install.bat`.

> Шлях краще без кирилиці й пробілів. `C:\ShortsTool` — саме те, що треба.

### Крок 3. ffmpeg
1. Відкрийте <https://github.com/BtbN/FFmpeg-Builds/releases/latest>.
2. Завантажте файл **`ffmpeg-master-latest-win64-gpl.zip`**. Має бути саме `win64-gpl` і `.zip`.
3. Створіть папку `C:\ShortsTool\ffmpeg` і розпакуйте архів у неї.
   Має вийти `C:\ShortsTool\ffmpeg\ffmpeg-master-latest-win64-gpl\bin\ffmpeg.exe`.

Інструмент знаходить ffmpeg там сам, у PATH нічого прописувати не треба.

### Крок 4. Драйвер NVIDIA
Оновіть драйвер відеокарти до свіжого (версія **570 або новіша**) через NVIDIA App / GeForce Experience
або з сайту nvidia.com. Після оновлення перезавантажте ПК.

> **RTX 50xx (наприклад, RTX 5070)** — це нове покоління Blackwell. Йому обов'язково потрібні
> драйвер 570+ і PyTorch, зібраний з CUDA 12.8. `install.bat` ставить саме таку версію (`cu128`),
> а `check_setup.bat` робить тестове обчислення на відеокарті й попередить, якщо щось не так.
> Процесор Ryzen 7500F не має вбудованої графіки, тож уся робота з відео йде на NVIDIA. Так і задумано.

### Крок 5. Бібліотеки
1. Двічі клацніть **`C:\ShortsTool\install.bat`**.
2. Зачекайте. Завантажується PyTorch з підтримкою відеокарти (~2,5 ГБ), тож це може тривати 10–30 хв.
3. Наприкінці запуститься перевірка. Вона ще раз завантажить моделі розпізнавання тексту (~100 МБ).
4. Внизу має бути напис **«Усе необхідне встановлено»**.

Якщо є рядки `[ПОМИЛКА]`, під кожним написано, що зробити. Повторно перевірити можна через `check_setup.bat`.
Пункт `[УВАГА] … зони ще не обведені` — це нормально, зони обводимо в наступному кроці.

Усе встановлюється в папку `C:\ShortsTool\venv` і на решту системи не впливає.

## Етап 1. Налаштування зон і перевірка на еталонному бою

### Крок 6. Обвести зони на кадрі з вашого запису
У кожного клієнта WoT і роздільності HUD стоїть трохи по-різному. Тому зони треба один раз обвести мишкою.

1. **Перетягніть файл запису** (mp4/mkv) мишкою **на `pick_zones.bat`**.
   Замість запису можна перетягнути скриншот з гри (png/jpg) у **тій самій роздільності**, що й запис.
2. У чорному вікні:
   - оберіть профіль: `wot`;
   - введіть секунду, де видно HUD у бою (лічильник уже не нуль, у лозі є рядки, напр. `1:35`).
3. Відкриється вікно з кадром. Праворуч список зон. Обведіть кожну, затиснувши ліву кнопку миші:

| Зона | Що обводити |
|---|---|
| **Вебкамера** | усю вебкамеру (піде нагору шортсу) |
| **Блок лічильників (V3)** | увесь блок «шкода / заблоковано / допомога» з іконками |
| **Число завданої шкоди** | лише перше число, із запасом праворуч під 5 цифр |
| **Лог подій** | область зелених/червоних рядків («612 Знищив …») |
| **Міцність — цифри** | «1650 / 2000» на панелі танка |
| **Міцність — смужка** | саму смужку міцності, на всю довжину повної смужки |
| **Екран смерті / кінця бою** | де з'являються «Оцініть бій», «Перемкнути камеру» |

Поради:
- Дрібні зони зручніше обводити в масштабі **100 %** або **200 %** (кнопки праворуч). Прокрутка — колесом миші, вбік — Shift + колесо.
- Щоб показати інший кадр (наприклад, екран смерті), введіть секунду внизу праворуч і натисніть «Показати». Уже обведені зони при цьому не зникають.
- Наприкінці натисніть **«Зберегти»**. Зони запишуться в `config\profiles\wot.json`, стара версія збережеться як `wot.json.bak`.
- Картинку з усіма зонами для перевірки знайдете в `C:\ShortsTool\output\zones_wot.png`.

### Крок 7. Перевірка на еталонному бою (FV215b 183)
1. **Перетягніть запис** з цим боєм **на `test_vision.bat`**.
2. Дайте відповіді на питання:
   - профіль — `wot`;
   - «З якого моменту почати» — за 10–20 с до початку бою. Не обов'язково обробляти весь 4-годинний запис;
   - «До якого моменту» — через ~30 с після смерті;
   - «Це еталонний бій?» — `т`;
   - «На якій секунді ЗАПИСУ починається бій» — момент, який у вашому списку був **0:00**. Тобто влучання +748 має бути на 8 с пізніше від цього моменту;
   - «Зберігати картинки зон» — `т`.
3. Наприкінці буде таблиця «ПОРІВНЯННЯ З ЕТАЛОНОМ». Критерій готовності — **5 з 5 влучань і смерть, ±1 с**.

> Еталон: 0:08 +748, 1:51 +583, 1:55 +600, 2:32 +1085, 3:34 +792, смерть ~3:43, підсумок 3 837.
> Сума п'яти влучань — 3 808, тобто є ще 29 шкоди (таран/пожежа/дрібне влучання).
> Тому одне «ЗАЙВЕ» дрібне влучання на +29 — нормально.

Де шукати результати:
- `output\reports\<запис>_vision_<дата>.csv` — звіт, відкривається в Excel подвійним кліком;
- `output\reports\<запис>_vision_<дата>.json` — те саме для програм;
- `output\debug\<запис>_<дата>\` — вирізані зони з тим, що розпізнано (у назві файлу: час і текст);
- `work\logs\` — детальний лог.

### Що надіслати мені після перевірки
1. Скопіюйте текст з чорного вікна від «Знайдено боїв» до кінця (або скриншот).
2. Надішліть картинку `output\zones_wot.png`.
3. Якщо щось **не знайдено** — заархівуйте папку `output\debug\<запис>_<дата>` і надішліть
   (або кілька картинок біля проблемних моментів). За ними я підлаштую пороги.

### Повторний аналіз без повторного сканування
Розпізнаний текст зберігається в `work\`. Якщо змінили пороги в `config\profiles\wot.json`,
перетягніть той самий запис на `test_vision.bat` і введіть ті самі межі. Збережені частини
підхопляться автоматично, і аналіз займе секунди. Якщо змінили **зони**, сканування буде нове.

Обробку можна перервати (закрити вікно або Ctrl+C). Наступного разу вона продовжиться
з останньої завершеної 10-хвилинної частини.

## Налаштування (без правки коду)

Усі параметри лежать у JSON-файлах. Їх можна правити Блокнотом. Ключі, що починаються з `_`, — це коментарі.

**`config\settings.json`** — загальне:
- `recording.mode` — `mixed` (зараз: одна доріжка, вебкамера в кадрі) або `separate`
  (пізніше: окремі доріжки гри й мікрофона та окремий файл вебкамери з OBS Source Record);
- `processing.chunk_minutes` — розмір частини обробки (пам'ять не росте на 4–8-годинних записах);
- `processing.hwaccel` — `cuda`: декодування відео на відеокарті;
- `ocr.*` — параметри розпізнавання тексту.

**`config\profiles\<гра>.json`** — профіль гри:
- `zones` — рамки (не правте вручну, використовуйте `pick_zones.bat`);
- `signals` — які джерела сигналів увімкнено: `vision` (екран), `game_audio` (звук гри), `voice` (ваш голос);
- `vision.damage_counter.max_jump` — найбільший правдоподібний приріст шкоди за постріл (за замовчуванням 3000).
  Більший стрибок вважається помилкою розпізнавання;
- `vision.end_screen.death_keywords` — написи екрану смерті. Можна додати свої;
- `vision.event_log.kill_keywords` — слова «знищення» в лозі;
- `battles.split_gap_s` — пауза після смерті, яка означає новий бій;
- `layout` — макет шортсу `split` / `overlay` (з етапу 3).

Якщо помилитесь у JSON (зайва кома тощо), інструмент покаже рядок з помилкою.
Завжди можна повернути попередню версію з файлу `.bak`.

## Як влаштовано всередині

```
C:\ShortsTool\
  install.bat, check_setup.bat, pick_zones.bat, test_vision.bat
  config\settings.json            загальні налаштування
  config\profiles\wot.json …      профілі ігор (зони, пороги, макет)
  samples\<гра>\                  зразки звуків гри (етап 2)
  shorts\config.py                завантаження налаштувань і профілів
  shorts\media.py                 ffmpeg/ffprobe, потік кадрів (лише читання оригіналу)
  shorts\ocr.py                   розпізнавання тексту (EasyOCR на GPU)
  shorts\vision_detector.py       зоровий детектор: сканування -> показання -> події -> бої
  shorts\events.py                спільний формат подій
  shorts\report.py                звіти CSV/JSON
  tools\pick_zones.py             вибір рамок мишкою
  tools\test_vision.py            перевірка етапу 1
  tools\check_setup.py            перевірка встановлення
  tools\reference_wot_fv215b.json еталонний бій
```

Як працює зоровий детектор:
1. ffmpeg декодує відео на відеокарті й двічі на секунду віддає лише ту частину кадру, де лежать зони.
2. Текст у зоні розпізнається, тільки коли зона змінилася (але не рідше ніж раз на секунду).
3. **Лічильник шкоди.** Значення лише зростає. Нове число приймається, коли воно однакове на двох незалежних читаннях поспіль. Неправдоподібні стрибки (понад `max_jump`) відкидаються. Обнулення (новий бій) приймається лише після 4 однакових кадрів. Час влучання — момент, коли число вперше змінилося.
4. **Лог.** Колір рядка визначається за пікселями: зелений — ваша шкода, червоний — отримана. Рядок «Знищив» — знищення ворога. Повтори того самого рядка не рахуються.
5. **Міцність.** Різке падіння — отримане влучання, 0 — вас знищено. Смужка використовується, якщо цифри не читаються.
6. **Екран смерті.** Раз на 2 с перевіряється напис «Оцініть бій» / «Перемкнути камеру». Подія фіксується лише в момент появи напису, а не весь час, поки ви спостерігаєте за боєм.
7. Події з різних зон зливаються: влучання з лічильника + зелений рядок логу = одне влучання з вищою впевненістю.

## Якщо щось не працює

| Повідомлення | Що зробити |
|---|---|
| `Не знайдено ffmpeg` | Перевірте крок 3: має існувати `C:\ShortsTool\ffmpeg\...\bin\ffmpeg.exe` |
| `CUDA недоступна` | Оновіть драйвер NVIDIA (крок 4), перезавантажте ПК, запустіть `install.bat` ще раз |
| `Python не знайдено` | Перевстановіть Python з галочкою «Add python.exe to PATH» |
| Влучання не знаходяться | Відкрийте `output\debug\…`. Якщо на картинках `dmg` не число шкоди — обведіть зону точніше через `pick_zones.bat` |
| Влучання знаходяться із запізненням | Надішліть мені звіт і папку debug — підлаштую пороги |
| Помилка в JSON | Виправте вказаний рядок або поверніть файл `.bak` |
