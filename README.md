# Автонарізка шортсів зі стрімів (World of Tanks, PUBG, STALKER 2…)

Інструмент знаходить найкращі моменти в записах стрімів і збирає вертикальні шортси
1080×1920 у DaVinci Resolve 21 (безкоштовна версія) так само, як ви робите вручну:
V1 — гра, V2 — вебкамера, V3 — лічильники шкоди, A1 — звук.
Усе працює локально на вашому ПК (NVIDIA), без хмарних сервісів і платних API.

## Стан розробки

| Етап | Що робить | Стан |
|---|---|---|
| 1 | Зоровий детектор WoT: блок лічильників, повідомлення про шкоду, таймер бою, екран смерті + звіт | **готово, потрібна перевірка на вашому записі** |
| 2 | Розділення звуку (голос/гра), звуки гри зі зразків, детектор емоцій, score | **готово, потрібна перевірка** |
| 3 | Відбір моментів, таймлайни V1/V2/V3 у DaVinci через кнопку в меню Workspace → Scripts | **готово, потрібна перевірка в DaVinci** |
| 4 | Рендер MP4 (NVENC) з тим самим макетом | **готово** |
| 5 | Субтитри whisper.cpp + заклик у кінці | **готово, потрібна перевірка** |

> **Коротко, як користуватися щодня (після встановлення):**
> 1. DaVinci → **Workspace → Scripts → Shorts Autocut** → у вікні оберіть запис, гру, впишіть заклик → «Почати».
> 2. Поки йде обробка, DaVinci вільний. Вікно показує прогрес.
> 3. Коли вікно напише «Готово» — у DaVinci знову **Workspace → Scripts → Shorts Autocut**:
>    з'являться таймлайни шортсів і таймлайн з маркерами. Готові MP4 — у `C:\ShortsTool\output\job_…`.

## Швидке встановлення (рекомендовано) — 3 кроки

1. **Завантажте один файл** `SETUP.bat`:
   відкрийте <https://github.com/MrAntibiotik/shorts-autocut/blob/main/SETUP.bat>
   і натисніть кнопку **Download raw file** (стрілка вниз праворуч над текстом файлу).
2. **Двічі клацніть** завантажений `SETUP.bat`.
   Якщо Windows покаже «Windows захистив ваш ПК», натисніть **Докладніше → Усе одно запустити**.
   Далі все піде саме, 20–60 хв. Установник:
   - перевірить драйвер NVIDIA і, якщо він застарий, відкриє сторінку завантаження;
   - поставить Python 3.11;
   - завантажить інструмент у `C:\ShortsTool`;
   - завантажить ffmpeg, PyTorch з CUDA, Demucs, EasyOCR, whisper.cpp і модель;
   - поставить кнопку в DaVinci і ярлик «Автонарізка шортсів» на робочий стіл;
   - наприкінці все перевірить.
3. **Перезапустіть DaVinci Resolve** і натисніть **Workspace → Scripts → Shorts Autocut**.
   При першому запуску для гри вікно саме запропонує обвести рамки на кадрі з вашого запису.

**Оновлення інструмента:** знову запустіть `SETUP.bat` (він лежить і в `C:\ShortsTool`).
Ваші налаштування, рамки, зразки звуків і результати при оновленні не чіпаються.

> Що лишається вручну: оновити драйвер NVIDIA, якщо він старіший за 570 (установник скаже про це),
> і перезапустити DaVinci. Якщо автоматичне встановлення десь зупинилось — надішліть текст
> із вікна, а поки можна пройти ручні кроки нижче.

## Ручне встановлення (лише якщо SETUP.bat не спрацював)

### Крок 1. Python 3.11
1. Відкрийте <https://www.python.org/downloads/windows/> і знайдіть **Python 3.11.x → Windows installer (64-bit)**.
2. Запустіть інсталятор. **Обов'язково** поставте галочку **«Add python.exe to PATH»** внизу першого вікна.
3. Натисніть **Install Now**. Нічого іншого не міняйте.

> Python 3.12 теж підійде. Не беріть 32-bit.

### Крок 2. Папка інструмента
1. Завантажте архів коду:
   <https://github.com/MrAntibiotik/shorts-autocut/archive/refs/heads/main.zip>
2. Розпакуйте його. Усередині є папка **`shorts-autocut-main`**.
3. Скопіюйте **вміст** папки `shorts-autocut-main` у **`C:\ShortsTool`**. Має вийти, наприклад, `C:\ShortsTool\install.bat`.

> Шлях краще без кирилиці й пробілів. `C:\ShortsTool` — саме те, що треба.

### Крок 3. ffmpeg
1. Відкрийте <https://github.com/BtbN/FFmpeg-Builds/releases/latest>.
2. Завантажте файл **`ffmpeg-master-latest-win64-gpl.zip`**. Має бути саме `win64-gpl` і `.zip`.
3. Створіть папку `C:\ShortsTool\ffmpeg` і розпакуйте архів у неї.
   Має вийти `C:\ShortsTool\ffmpeg\ffmpeg-master-latest-win64-gpl\bin\ffmpeg.exe`.

Інструмент знаходить ffmpeg там сам, у PATH нічого прописувати не треба.

### Крок 4. Драйвер NVIDIA
Оновіть драйвер відеокарти до свіжого (версія **570 або новіша**) через NVIDIA App / GeForce Experience
або з сайту nvidia.com. Після оновлення перезавантажте ПК.

> **RTX 50xx (наприклад, RTX 5070)** — це нове покоління Blackwell. Йому обов'язково потрібні
> драйвер 570+ і PyTorch, зібраний з CUDA 12.8. `install.bat` ставить саме таку версію (`cu128`),
> а `check_setup.bat` робить тестове обчислення на відеокарті й попередить, якщо щось не так.
> Процесор Ryzen 7500F не має вбудованої графіки, тож уся робота з відео йде на NVIDIA. Так і задумано.

### Крок 5. Бібліотеки
1. Двічі клацніть **`C:\ShortsTool\install.bat`**.
2. Зачекайте. Завантажується PyTorch з підтримкою відеокарти (~2,5 ГБ), тож це може тривати 10–30 хв.
3. Наприкінці запуститься перевірка. Вона ще раз завантажить моделі розпізнавання тексту (~100 МБ).
4. Внизу має бути напис **«Усе необхідне встановлено»**.

Якщо є рядки `[ПОМИЛКА]`, під кожним написано, що зробити. Повторно перевірити можна через `check_setup.bat`.
Пункт `[УВАГА] … зони ще не обведені` — це нормально, зони обводимо в наступному кроці.

Усе встановлюється в папку `C:\ShortsTool\venv` і на решту системи не впливає.

## Етап 1. Налаштування зон і перевірка на еталонному бою

### Крок 6. Обвести зони на кадрі з вашого запису
У кожного клієнта WoT і роздільності HUD стоїть трохи по-різному. Тому зони треба один раз обвести мишкою.

1. **Перетягніть файл запису** (mp4/mkv) мишкою **на `pick_zones.bat`**.
   Замість запису можна перетягнути скриншот з гри (png/jpg) у **тій самій роздільності**, що й запис.
2. У чорному вікні:
   - оберіть профіль: `wot`;
   - введіть секунду, де видно HUD у бою (лічильник уже не нуль, у лозі є рядки, напр. `1:35`).
3. Відкриється вікно з кадром. Праворуч список зон. Обведіть кожну, затиснувши ліву кнопку миші:

| Зона | Що обводити |
|---|---|
| **Вебкамера** | усю вебкамеру (у шортсі — вікно зверху по центру) |
| **Блок лічильників (V3)** | три рядки «шкода / заблоковано / допомога» з іконками зліва внизу, із запасом праворуч під 5 цифр. Верхнє число — завдана шкода, його зростання = влучання. У шортсі блок стоїть одразу під вебкамерою |
| **Повідомлення про шкоду** | рядок посередині екрана «941 ✕ Шкода пострілом ◆ Progetto 65» — з запасом по ширині (кадр, де воно видно) |
| **Таймер бою** | час праворуч угорі («12:47») — за ним визначаються межі боїв |

Більше нічого обводити не треба. Екран смерті («Оцініть бій») шукається в центрі екрана, а число шкоди
береться з верхнього рядка блоку лічильників. Якщо колись знадобиться задати їх вручну, поставте в профілі
`"show_optional_zones": true`, і вони з'являться у вікні.

Рамки за замовчуванням уже виставлені за вашим скріном (запис 21:9). Їх треба лише перевірити й за потреби підправити.

Поради:
- Дрібні зони зручніше обводити в масштабі **100 %** або **200 %** (кнопки праворуч). Прокрутка — колесом миші, вбік — Shift + колесо.
- Щоб показати інший кадр (наприклад, екран смерті), введіть секунду внизу праворуч і натисніть «Показати». Уже обведені зони при цьому не зникають.
- Наприкінці натисніть **«Зберегти»**. Зони запишуться в `config\profiles\wot.json`, стара версія збережеться як `wot.json.bak`.
- Картинку з усіма зонами для перевірки знайдете в `C:\ShortsTool\output\zones_wot.png`.

### Крок 7. Перевірка на еталонному бою (FV215b 183)
1. **Перетягніть запис** з цим боєм **на `test_vision.bat`**.
2. Дайте відповіді на питання:
   - профіль — `wot`;
   - «З якого моменту почати» — за 10–20 с до початку бою. Не обов'язково обробляти весь 4-годинний запис;
   - «До якого моменту» — через ~30 с після смерті;
   - «Це еталонний бій?» — `т`;
   - «На якій секунді ЗАПИСУ починається бій» — момент, який у вашому списку був **0:00**. Тобто влучання +748 має бути на 8 с пізніше від цього моменту;
   - «Зберігати картинки зон» — `т`.
3. Наприкінці буде таблиця «ПОРІВНЯННЯ З ЕТАЛОНОМ». Критерій готовності — **5 з 5 влучань і смерть, ±1 с**.

> Еталон: 0:08 +748, 1:51 +583, 1:55 +600, 2:32 +1085, 3:34 +792, смерть ~3:43, підсумок 3 837.
> Сума п'яти влучань — 3 808, тобто є ще 29 шкоди (таран/пожежа/дрібне влучання).
> Тому одне «ЗАЙВЕ» дрібне влучання на +29 — нормально.

Де шукати результати:
- `output\reports\<запис>_vision_<дата>.csv` — звіт, відкривається в Excel подвійним кліком;
- `output\reports\<запис>_vision_<дата>.json` — те саме для програм;
- `output\debug\<запис>_<дата>\` — вирізані зони з тим, що розпізнано (у назві файлу: час і текст);
- `work\logs\` — детальний лог.

### Що надіслати мені після перевірки
1. Скопіюйте текст з чорного вікна від «Знайдено боїв» до кінця (або скриншот).
2. Надішліть картинку `output\zones_wot.png`.
3. Якщо щось **не знайдено** — заархівуйте папку `output\debug\<запис>_<дата>` і надішліть
   (або кілька картинок біля проблемних моментів). За ними я підлаштую пороги.

### Повторний аналіз без повторного сканування
Розпізнаний текст зберігається в `work\`. Якщо змінили пороги в `config\profiles\wot.json`,
перетягніть той самий запис на `test_vision.bat` і введіть ті самі межі. Збережені частини
підхопляться автоматично, і аналіз займе секунди. Якщо змінили **зони**, сканування буде нове.

Обробку можна перервати (закрити вікно або Ctrl+C). Наступного разу вона продовжиться
з останньої завершеної 10-хвилинної частини.

## Етап 2. Звук: розділення, звуки гри, ваші емоції

### Крок 8. Доставити нові бібліотеки
Якщо ви вже ставили етап 1, ще раз запустіть **`install.bat`**. Він доставить Demucs (розділення звуку),
librosa і SciPy. Наприкінці `check_setup` один раз завантажить модель розділення (~80 МБ)
і покаже швидкість, наприклад «10 с звуку за 0.3 с».

### Крок 9. Бібліотека зразків звуків гри
Інструмент шукає в звуці гри знайомі звуки зі зразків. Зразки лежать у `samples\<гра>\<категорія>\`:

| Категорія (WoT) | Що це | Що означає |
|---|---|---|
| `пробиття` | голос екіпажу «Пробиття!» / «Є пробиття!» | влучання |
| `попадання` | звук влучання без пробиття | слабке влучання |
| `ваншот` | звук/голос знищення одним пострілом | знищення (вага ×2) |
| `знищено` | «Ворога знищено!» / «Ціль знищено!» | знищення ворога |
| `мене_пробили` | «Нас пробили!» та подібне | отримав шкоду |

Найпростіше вирізати зразки з ваших записів:
1. Перетягніть запис на **`make_sample.bat`**.
2. Оберіть профіль `wot` і звідки брати звук:
   - **1 — мікс**: для голосу екіпажу, коли ви мовчите;
   - **2 — доріжка гри**: для пострілів і вибухів, нейромережа прибере ваш голос;
   - **3 — доріжка голосу**: для голосу екіпажу, якщо ви говорите поверх. Нейромережа відносить мову екіпажу до «голосу».
3. Введіть початок і кінець звуку з точністю до десятих, наприклад `1:51.2` і `1:52.0`. Довжина — 0,3–2 с.
4. Оберіть категорію або введіть нову назву (інструмент спитає, що вона означає).
5. Можна одразу прослухати зразок і вирізати наступний.

На кожну категорію вистачить **2–5 зразків** з різних боїв. Можна класти й готові WAV-файли прямо в папки.

> **Без зразків** етап теж працює: пропускається лише підтвердження звуком.
> Детектор голосу працює одразу.

### Крок 10. Перевірка
1. Перетягніть запис на **`test_audio.bat`**.
2. Відповіді на питання:
   - профіль — `wot`;
   - відрізок — для першої перевірки 5–30 хв, наприклад той самий еталонний бій з запасом;
   - «Зберегти доріжки голос і гра» — `т`.
3. Що побачите:
   - по кожному бою — моменти зі **score** і поясненням, звідки бали: «звук: пробиття (0.81); реакція: крик через 1.2 с»;
   - **підсумок**: скільки звуків гри знайдено, скільки криків/сміху/сплесків, скільки подій з екрану підтверджено звуком;
   - для порівняння — скільки просто «сплесків гучності» в міксі. У завданні їх було ~50 на 5 реальних влучань, тому сам звук без екрану для WoT не годиться.
4. Послухайте `output\audio\…_голос.wav` і `…_гра.wav`. Так видно, наскільки добре нейромережа відокремила ваш голос.

Звукова частина теж кешується в `work\`. Повторний запуск після зміни порогів займає секунди;
нове розділення робиться, лише якщо змінили режим запису або модель.

### Як рахується score (сила моменту)
- **Бали за тип події:** влучання 1, знищення ворога 3, моя смерть 2,5, отримав шкоду 0,8.
- **Влучання:** + шкода / 500, не більше +3. Постріл на 1085 «сильніший» за 583.
- **Підтвердження звуком:** якщо в межах ±1 с є звук гри зі зразків — × 1,3.
- **Ваша реакція:** якщо протягом 0–3 с після події ви закричали, засміялися чи різко гучно сказали щось — + 1 × інтенсивність.
- **Ігри без зорових сигналів (PUBG, STALKER 2):** моментами стають самі звуки гри (зразки й гучні звуки — постріли, вибухи) і ваші реакції.

Усі числа — у профілі гри, розділ `scoring`.

### Що надіслати мені після перевірки етапу 2
1. Текст з чорного вікна від таблиці боїв до «ПІДСУМОК ЗВУКУ» включно.
2. Вашу оцінку на слух: чи чисто відділено голос (`…_голос.wav`) і чи не лишилось вашого голосу в `…_гра.wav`.
3. Якщо пропущено явний крик/сміх або знайдено зайве — час цих моментів. Підлаштую пороги.

## Етапи 3–5. Шортси в DaVinci, готові MP4, субтитри

### Крок 11. Субтитри: whisper.cpp і модель
Запустіть **`setup_whisper.bat`**. Він:
1. Завантажить з GitHub готову збірку whisper.cpp для Windows з CUDA і розпакує її в папку `whisper`.
2. Запитає модель. Рекомендовано **1 — large-v3-turbo** (~1,6 ГБ, добре знає українську).
   Якщо завантаження обірветься — запустіть ще раз, воно продовжиться.
3. Зробить пробне розпізнавання на відеокарті.
   - **Про RTX 5070.** Офіційна збірка зроблена з CUDA 12.4, тому при першому запуску драйвер сам допідготує код під вашу відеокарту. Це може зайняти хвилину, потім працює швидко.
   - **Якщо відеокарта не спрацює,** скрипт перевірить процесор і сам перемкне налаштування. Субтитри будуть повільніші, але будуть.

### Крок 12. Кнопка в DaVinci
1. Запустіть **`install_resolve.bat`**. Він покладе два файли в
   `%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Fusion\Scripts\Utility\`:
   - **Shorts Autocut** — запуск обробки / збирання результату;
   - **Shorts Reimport Last** — зібрати останній результат ще раз (якщо щось пішло не так).
2. **Перезапустіть DaVinci Resolve** (повністю закрийте й відкрийте).
3. Відкрийте проєкт → меню **Workspace → Scripts** → там з'являться обидві кнопки.

> Уся логіка лежить у `C:\ShortsTool\resolve\shorts_lib.lua`, тому після оновлення інструмента
> кнопки перевстановлювати не треба.

### Крок 13. Попередній перегляд макета (рекомендую перед першою обробкою)
Перетягніть запис на **`preview_layout.bat`**, оберіть гру і секунду. Відкриється картинка 1080×1920
саме такого вигляду, як шортс: гра, вебкамера, лічильники, приклад субтитру й заклику.
Якщо щось не там:
- рамки на кадрі гри — `pick_zones.bat`;
- розміщення в шортсі — `config\profiles\<гра>.json`, розділ `layout` (пояснення всередині).

### Крок 14. Перша повна обробка
1. Відкрийте в DaVinci проєкт, куди класти шортси (можна новий).
2. Можна виділити запис у медіапулі — тоді він підставиться у вікно сам.
3. **Workspace → Scripts → Shorts Autocut** → відкриється вікно:
   - **Запис(и)** — «Додати…» (можна кілька);
   - **Профіль гри** — World of Tanks / PUBG / …;
   - **Відрізок** — для першої спроби візьміть 15–30 хв (наприклад, `1:00:00` – `1:20:00`), щоб швидко побачити результат;
   - **Заклик** — текст у кінці кожного шортсу. Останній текст запам'ятовується; порожньо — без заклику;
   - галочки: рендер MP4, субтитри, відділення голосу.
4. **Почати.** Вікно покаже етапи, прогрес і орієнтовний час, що залишився.
   Можна зупинити — готові частини збережуться.
5. Після «Готово» натисніть **Workspace → Scripts → Shorts Autocut** ще раз. Що з'явиться в DaVinci:
   - папка в медіапулі «Шортси <дата>»;
   - таймлайн **«<запис> — моменти»** з маркерами всіх моментів. Колір: зелений — влучання, червоний — отримав шкоду,
     жовтий — знищив ворога, фуксія — мене знищено, блакитний — ваша емоція, синій — звук гри.
     У назві маркера — шкода;
   - на кожен бій таймлайн **«Шортс NN — бій …»** 1080×1920, 60 fps:
     - **V1** — гра (центр кадру);
     - **V2** — вебкамера;
     - **V3** — лічильники (тільки WoT);
     - **V4** — титр заклику (Text+, текст можна змінити в Inspector);
     - **A1** — звук;
     - доріжка **субтитрів**.

     Рамки задані через **Zoom / Position / Crop** у Inspector — їх можна підправити вручну.
   - вікно-підсумок: скільки зібрано і чи були зауваження. Деталі — у `work\logs\resolve_import.log`.

Що лежить у папці `output\job_<дата>\`:
- `…_short_01.mp4` — готовий шортс (H.264 NVENC, 1080×1920, 60 fps, вшиті субтитри й заклик);
- `…_short_01.srt` — субтитри окремо;
- `…_report.csv` — звіт для Excel: бій, таймкоди, тип, шкода, score, джерело, у який кліп потрапило;
- `…_markers.edl` — маркери для DaVinci (якщо треба вручну: ПКМ по таймлайну в медіапулі → Timelines → Import → Timeline Markers from EDL).

### Правки після обробки
- **Межі моментів у DaVinci:** кліпи кожного шматка (V1 гра, V2 камера, V3 лічильники, A1 звук) **зв'язані**:
  - потягніть край будь-якого з них — разом зсунуться всі чотири;
  - Delete / Shift+Delete прибирає шматок цілим;
  - кліпи взято з повного запису, тож межу можна тягнути й назовні, щоб додати секунди.

  Щоб змінити рамку лише одного шару (наприклад, Zoom камери в Inspector), клацніть по ньому з **Alt**.
  Без Alt Inspector змінить усі виділені кліпи. Розв'язати шматок: ПКМ → Link Clips.
  Субтитри й заклик лежать окремо — після великих зсувів підсуньте їх.
- **У DaVinci:** текст субтитрів правте прямо на доріжці субтитрів, заклик — у Inspector титру Text+, рамки — в Inspector кліпів V1–V3. Рендер — звичайним Deliver.
- **Готові MP4 без DaVinci:**
  1. Виправте Блокнотом `…_short_NN.srt` (можна додати емодзі 😱🔥) або `…_short_NN_cta.txt`.
  2. Перетягніть папку `output\job_…` на **`rerender.bat`** і вкажіть номери шортсів.

### Як відбираються моменти (етап 3)
- **Один бій — один шортс до 60 с.** Межі боїв для WoT визначаються так:
  - обнулення лічильника шкоди;
  - екран смерті / кінця бою;
  - пауза після смерті.

  Для ігор без зорових сигналів — паузи між скупченнями подій.
- **Відбір:**
  1. Беруться найсильніші моменти бою (за score) із запасом 2–3 с до і після. Сильніший момент — більший запас.
  2. Моменти ближче 4 с один до одного зливаються.
  3. Фінальний момент (ваша смерть або останнє знищення) включається завжди.
  4. Шматки йдуть у хронологічному порядку.
- **Межі підганяються під паузи у вашій мові** — до 1,5 с у кожен бік, щоб не різати фразу.
- **Отримана шкода** потрапляє в шортс лише якщо вона велика або ви на неї відреагували.
  Дрібна шкода (< 100: пожежа, таран) моментом не вважається.
- Бій без вартих моментів пропускається (`selection.min_battle_score`).
- Перевірено на еталонному бою FV215b (на штучних даних):
  - відібрано 0:05.5–0:11 / 1:48.6–1:57.9 / 2:28.8–2:35.2 / 3:31.4–3:44.2 ≈ 34 с;
  - ваш еталон — 0:06–0:11 / 1:49–1:57 / 2:30–2:36 / 3:31–3:44 ≈ 32 с.

### Субтитри (етап 5)
- whisper.cpp розпізнає **вашу доріжку голосу** (або мікс, якщо розділення вимкнене) українською.
  Усі шматки розпізнаються одним запуском, тож модель завантажується один раз.
- **Фрази:**
  - короткі: до 24 символів у рядку, 1–2 рядки, до 2,8 с;
  - розриваються на паузах і розділових знаках;
  - не переходять через склейку шматків.
- **Захист від «галюцинацій» whisper:**
  - слова в моменти, коли ви мовчали, відкидаються;
  - фрази на кшталт «Дякую за перегляд» видаляються (список — `whisper.hallucinations`).
- **Емодзі:**
  - якщо в момент фрази ви кричали — 😱, сміялися — 😂;
  - за словами: «знищ…» 💥, «пробит…» 🎯, «ваншот» 🔥.

  Налаштовується або вимикається в `subtitles.emotion_emoji` / `keyword_emoji`.
- **Стиль у MP4:**
  - великий білий жирний шрифт (Arial Bold) з чорним контуром і тінню;
  - по центру, одразу під блоком лічильників (`layout.subtitles_y` = 1450, тобто ~75 % висоти);
  - кольорові емодзі (Segoe UI Emoji).
- **У DaVinci** субтитри лежать на доріжці субтитрів. Їхній вигляд (шрифт, розмір, позиція) задається один раз
  у налаштуваннях доріжки: клік по доріжці субтитрів → Inspector → Track → Style.

## Налаштування (без правки коду)

Усі параметри лежать у JSON-файлах. Їх можна правити Блокнотом. Ключі, що починаються з `_`, — це коментарі.

**`config\settings.json`** — загальне:
- `recording.mode` — `mixed` (зараз: одна доріжка, вебкамера в кадрі) або `separate`
  (пізніше: окремі доріжки гри й мікрофона та окремий файл вебкамери з OBS Source Record);
- `processing.chunk_minutes` — розмір частини обробки (пам'ять не росте на 4–8-годинних записах);
- `processing.hwaccel` — `cuda`: декодування відео на відеокарті;
- `ocr.*` — параметри розпізнавання тексту;
- `separation.enabled` — розділення голос/гра нейромережею (для `mixed`). `false` — працювати по міксу;
- `separation.shifts` — `0` швидко, `1–2` трохи якісніше, але повільніше.

**`config\profiles\<гра>.json`** — профіль гри:
- `zones` — рамки (не правте вручну, використовуйте `pick_zones.bat`);
- `signals` — які джерела сигналів увімкнено: `vision` (екран), `game_audio` (звук гри), `voice` (ваш голос);
- `vision.damage_counter.max_jump` — найбільший правдоподібний приріст шкоди за постріл (за замовчуванням 3000).
  Більший стрибок вважається помилкою розпізнавання;
- `vision.end_screen.death_keywords` — написи екрану смерті. Можна додати свої;
- `vision.event_log.kill_keywords` — слова «знищення» в лозі;
- `battles.split_gap_s` — пауза після смерті, яка означає новий бій;
- `game_audio.categories` — категорії зразків звуків і що вони означають (`hit`, `kill`, `damage_taken`, `game_sound`) + вага;
- `game_audio.threshold` — поріг схожості зі зразком (0..1; вище — суворіше);
- `game_audio.loudness_spikes` — гучні звуки гри (увімкнено для PUBG/STALKER 2);
- `voice.spike_db` — на скільки дБ гучніше за ваш звичайний рівень вважається сплеском (по міксу — `mix_spike_db`);
- `voice.scream_min_hz` — від якого тону сплеск вважається криком; `voice.laugh` — параметри сміху;
- `scoring` — бали й бонуси моментів (див. вище);
- `selection` — відбір: `max_duration_s` (60), запаси `pre_s`/`post_s`, `merge_gap_s`, `min_score`, `min_battle_score`, підгонка під паузи `speech_snap`/`snap_max_s`, `max_shorts` (0 — без обмеження);
- `layout` — макет шортсу: `preset` (`overlay` — гра на весь кадр, вебкамера поверх зверху; `split` — вебкамера смугою, гра під нею), `webcam_fit` (`contain` — камера ціла без обрізання, `cover` — заповнити рамку з обрізанням), `game_below_webcam` (зсунути гру так, щоб приціл був під камерою), `webcam_height` (для `contain` — найбільша висота камери, 0 — без обмеження), висота вебкамери, вікно вебкамери для overlay, `game_zoom`, `game_offset_x/y`, `counters` (позиція V3), `subtitles_y`.

**`config\settings.json`** — ще:
- `render` — кодек (NVENC; якщо не працює — автоматично процесор), якість `cq`;
- `whisper` — модель, мова, `gpu`, `prompt` (слова-підказки: назви танків, сленг), `hallucinations`;
- `subtitles` — шрифт, розмір, кольори, контур, тінь, довжина фраз, емодзі;
- `cta` — тривалість заклику (3 с), розмір шрифту, висота;
- `resolve` — кольори маркерів; `link_clips` — зв'язувати кліпи шматка (`true` / `false`); службові `mismatch_mode`, `crop_units`, `tilt_up_positive` (див. «Якщо щось не працює»).

Якщо помилитесь у JSON (зайва кома тощо), інструмент покаже рядок з помилкою.
Завжди можна повернути попередню версію з файлу `.bak`.

Як працює зоровий детектор:
1. ffmpeg декодує відео на відеокарті й двічі на секунду віддає лише ту частину кадру, де лежать зони.
2. Текст у зоні розпізнається, тільки коли зона змінилася (але не рідше ніж раз на секунду).
3. **Лічильник шкоди** (верхній рядок блоку лічильників). Значення лише зростає. Нове число приймається, коли воно однакове на двох незалежних читаннях поспіль. Неправдоподібні стрибки (понад `max_jump`) відкидаються. Обнулення (новий бій) приймається лише після 4 однакових кадрів. Час влучання — момент, коли число вперше змінилося.
4. **Повідомлення про шкоду** посередині екрана («941 ✕ Шкода пострілом»). Нове повідомлення = точний момент влучання і його шкода. Воно підтверджує влучання з лічильника й уточнює його час. Якщо лічильник щось пропустив, влучання все одно буде знайдене.
5. **Таймер бою** праворуч угорі (15:00 → 0:00) визначає межі боїв:
   - **початок** — момент, коли таймер почав відлік (рахується назад від показаного часу, тож працює навіть, якщо запис почався посеред бою);
   - **новий бій** — таймер стрибнув угору;
   - **кінець** — таймер зник більше ніж на 30 с (результати, ангар).
   - Лог рядків і смужка міцності за замовчуванням вимкнені. Їх можна ввімкнути в профілі (`vision.event_log` / `vision.hp`).
6. **Екран смерті.** Раз на 2 с перевіряється напис «Оцініть бій» / «Перемкнути камеру». Подія фіксується лише в момент появи напису, а не весь час, поки ви спостерігаєте за боєм.
7. Події з різних зон зливаються: влучання з лічильника + повідомлення в центрі = одне влучання з вищою впевненістю.
   Початок бою за таймером і обнулення лічильника — одна межа.

## Якщо щось не працює

| Повідомлення | Що зробити |
|---|---|
| `Не знайдено ffmpeg` | Перевірте крок 3: має існувати `C:\ShortsTool\ffmpeg\...\bin\ffmpeg.exe` |
| `CUDA недоступна` | Оновіть драйвер NVIDIA (крок 4), перезавантажте ПК, запустіть `install.bat` ще раз |
| `Python не знайдено` | Перевстановіть Python з галочкою «Add python.exe to PATH» |
| Влучання не знаходяться | Відкрийте `output\debug\…`. Якщо на картинках `dmg` не число шкоди — обведіть зону точніше через `pick_zones.bat` |
| Влучання знаходяться із запізненням | Надішліть мені звіт і папку debug — підлаштую пороги |
| Помилка в JSON | Виправте вказаний рядок або поверніть файл `.bak` |
| `Розділення звуку недоступне` | Запустіть `install.bat` ще раз; для перевірки — `check_setup.bat`. Поки що інструмент працює по міксу |
| `CUDA out of memory` при розділенні | Закрийте гру/OBS під час обробки або поставте `separation.device` = `cpu` (повільно) |
| Ваш голос знаходиться як «звук гри» або навпаки | Підніміть `game_audio.threshold` (напр. 0.7) або виріжте чистіші зразки |
| У меню Workspace → Scripts немає кнопок | Запустіть `install_resolve.bat`, **повністю** перезапустіть DaVinci |
| Кнопка нічого не робить | Workspace → Console покаже помилку; лог — `work\logs\resolve_import.log`. Можна запустити `run_job.bat` вручну, а потім натиснути кнопку для імпорту |
| На таймлайні шортсу рамки не там (V2 показує не вебкамеру тощо) | Надішліть мені скриншот і `resolve_import.log`.
